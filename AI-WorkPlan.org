* Overview, Purpose and Context

<<Overview>>

bisos.gitist is a bisos-pip package (=py3/bisos/gitist/=, executables in =py3/bin=), a seed/plant
tool on =bisos.csSeed='s =csCmndsList=. The name is git+ist, as in artist: the eventual scope is all
things git. Today it mass-clones for two brands, *gitlab* (python-gitlab) and *github* (PyGithub),
through brand-neutral commands over a thin brand adapter (=RepoRef=); see AI-DevStatus.org for the
architecture, the config files kept outside the repo, and what is verified.

- Commands live in =py3/bisos/gitist/gitist_csu.py=; =whichReactFramework= and =placeHolder= there are
  templates for new ones. Register each in the seed's example menu (=examples_csu= / =examples_seed=).
- No unit tests: verify by running the plants of =py3/bin/gitist-seed.cs=
  (=py3/bin/pub-{anon,auth}-{github,gitlab}-gitist.pcs=) and comparing with the =captureRunStr(...)=
  blocks in each command. (AI-DevStatus.org still names them =gitist.cs=, =gitlab-pub-gitist.pcs=.)
- Runtime interpreter: =/bisos/venv/py3/dev-bisos3/bin/python= (editable install there).
- gitist is where the gitGroup concept lands (bisos-pip/overview WorkPlan Stage 3): a collection of
  repos independent of the git server (GitHub organization, GitLab group/subgroup). Stage 7 (replacing
  =bx-gitRepos=) starts with the gitGroup consistency engine (bisos-pip/overview WorkPlan 5.1).

The model and terminology of ./README.org will be used through out.

The ./DESIGN.org is used to drive this workplan.

* Stage 7 TODOs --- bx-gitRepos Replacement

<<Stage 7>>

Goal: gitist becomes the modern way of doing what =bx-gitRepos= (=/bisos/core/bsip/bin/bx-gitRepos=,
bash) does. =bx-gitRepos= is *not* obsoleted: it stays as is, beside gitist (user, 2026-11-15). Start
with what bisos-pip/overview WorkPlan 5.1 asks for: a *gitGroup consistency engine*. A gitGroup is a
directory of repos (bisos-pip: =/bisos/git/bxRepos/bisos-pip/*=); its *rules* say what every member
repo must have. The engine reports, per repo and rule, a status with the action it implies; a
separate update applies only the safe actions.

Decided (user, 2026-11-15; overview Stage 5): general for any gitGroup; the engine here; each
gitGroup's rules declared in its overview repo; =py3/README.rst= / =py3/_description.org= ignored and
untracked; the =pipPkgsStatus= pattern (bisos.pycs) of read-only status, then explicit action.

Design proposal (7.1 settles it):
- *A new seed family*, csSeed's triple: =gitGroup_seed.py= (atexit -> =gitGroup-seed.cs=),
  =gitGroup_seedInfo.py= (singleton; =setup(base=..., exclude=[...], rules=[...])=), =gitGroup_csu.py=
  (the Cmnds and rule logic), =py3/bin/gitGroup-seed.cs=.
- *The plant* lives in the gitGroup's overview repo as =py3/bin/<gitGroup>_gitGroup.pcs= (bisos-pip:
  =bisos-pip/overview/py3/bin/bisos-pip_gitGroup.pcs=; the prefix keeps the plants of different
  gitGroups apart): names the base, any members to leave out, and the rules. Used as
  =bisos-pip_gitGroup.pcs -i gitGroup_status=, then =-i gitGroup_update=. The overview repo gets a
  =py3/bin/= but no =setup.py=: it stays a non-package (not installed, not on PATH).
- *Members*: the children of base that are git repos, minus =exclude=.
- *Rule factories* (as =pkgsSeed.pipPkg=):
  - =fileFromTemplate(path, template)= --- the repo's =path= equals =template=. Statuses: =ok=,
    =missing= (safe: add), =stale= (an exact copy of an earlier version of the template, found
    through the template's git history in its own repo: safe to replace), =custom= (differs from
    every version: show the diff; the user decides).
  - =notTracked(paths)= --- these are not tracked. Status =tracked= (action: =git rm --cached=,
    printed, not run: staging is the user's).
  - Later: =exists(path)=, the AI-Activity layout (current / old / none), =LICENSE=, =README.org=.
- *Cmnds*: =gitGroup_members=; =gitGroup_status [repo ...]= (read-only: a table of repo x rule, then
  counts); =gitGroup_diff <repo> <rule>= (for =custom=); =gitGroup_update [repo ...]= (writes only
  =missing= and =stale= files into the working tree; never stages or commits; prints the =git rm
  --cached= lines for =tracked=).
- The modern counterpart, for a gitGroup, of =bx-gitRepos -i baseUpdateDotIgnore= /
  =baseVerifyDotIgnore= (which stay).
- Known state to test against (overview 5.1's survey): of 76 repos, =.gitignore= 1 current, 10 stale,
  44 one shared older copy, ~5 unique, 16 missing; =.gitattributes= 59 ok, 17 missing; 57 track
  =py3/README.rst=.
